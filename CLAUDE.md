# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`bevy-react` drives **`bevy_ui` from a React app** running on an embedded V8 (deno_core) runtime. It is a **Rust crate + JS package** (one repo) plus an example app. React renders through a custom reconciler that emits UI-mutation ops; Rust applies them to the Bevy ECS; interactions and app-level messages flow back.

This is a virtual Cargo workspace: `crates/bevy-react` is the **facade** an app depends on (package `bevy-react`, lib `bevy_react` — see "Architecture: the plugin group & cargo features"), `crates/core` is the `bevy_react_core` lib (the bridge, the engines, the element registry + extension contract, and the core elements `node`/`button`/`text`/`textSpan`/`editableText`/`image`/`root`), `crates/macros` the `bevy_react_macros` proc-macro crate, and five **feature crates**, each one element registered through the same public API a third party would use (see "Architecture: the element registry"): `crates/svg` (`bevy_react_svg`, the JSX `<svg>` + shapes), `crates/anchor` (`<anchor>`), `crates/canvas` (`<canvas>`), `crates/portal` (`<portal>`), `crates/surface` (`<surface>`). Svg-mode `<image>` support, the animation engine, the named render-target registry (`render_target`), and the CPU raster helpers (`raster`) are public modules of `core`. The examples (`examples/{demos,minimal,stress,layers-stress}`) are their own workspace packages (`publish = false`), each depending on the facade with the features it uses (`demos`: the defaults, i.e. everything; `minimal`: none — core only; the two stress benches: `devtools`); `demos` adds `ReactPlugins` (every feature plugin beside `ReactUiPlugin`), plus two app-authored extensions registered through the same API: the `<cube>` element (`examples/demos/cube/` — a node-less, detached 3D mesh entity with animatable attributes; it adds bevy's `MeshPickingPlugin` with `require_markers`, so only handler-bearing cubes, which get a `Pickable`, are ray-cast by the `MeshPickingCamera`-marked shared camera) and the `sparkle` style property (`examples/demos/sparkle/` — auto-stamped `StyleValue<Sparkle>`, particles in an app-owned overlay root). It is **also** an npm workspace (root `package.json` with members `js` and `examples/demos/ui`). The two halves are developed together.

The example (`examples/demos`) is a gallery: a left-nav switches between demos, and React drives the active 3D scene with `bevy.selectScene(id)` (or `null` for an empty viewport). The three scenes each live under `examples/demos/scenes/` as a **separate Bevy plugin**: `cubes.rs` (cubes driven by `emit`), `bouncing_ball.rs` (one ball that both pushes Bevy→React events as toasts and answers request/response polls, and owns its own ball physics), and `crowded_cubes.rs` (crowded cubes with world-anchored badges). Only one scene runs at a time: React `emit`s the selection, and a `States` enum (`Scene` in `examples/demos/scene.rs`, variants `None | Cubes | BouncingBall | CrowdedCubes`) gates each scene's systems, with `DespawnOnExit(Scene::…)` scoping its entities. The shared 3D camera (auto-orbit + drag + zoom) is bundled as `CameraPlugin` in `examples/demos/camera.rs`.

## Commands

Build / run the example (this is the main way to see it working):

```sh
npm install                          # once
npm run build -w demos           # build the React bundles — REQUIRED before running
cargo run -p demos   # run the Bevy app (needs a GPU/window)
npm run watch -w demos           # rebuild app bundle on change → React Fast Refresh
```

The build (`examples/demos/ui/build.mjs`, via `bevy-react/build-lib`) emits **two**
bundles into `dist/`: `vendor.js` (react + react-reconciler + the bevy-react runtime,
loaded into the isolate once and never re-run) and `app.js` (the app's own components,
an IIFE re-executed on each edit). Editing a component preserves its `useState`/hook
state — see "Hot reload: React Fast Refresh" below.

Tests:

```sh
cargo test                           # all Rust tests (whole workspace)
cargo test -p bevy_react_core --lib       # just the core library unit tests
cargo test -p bevy_react_core --lib ts_codegen::tests::exports_typescript   # a single test by path
cargo test -p bevy_react_svg               # a feature crate (its op-path tests run on core's `test_util` harness)
cargo test -p bevy_react_anchor -p bevy_react_canvas -p bevy_react_portal -p bevy_react_surface
cargo test -p bevy-react --features bevy/x11   # the facade (group + KNOWN_FEATURES pins, macros without serde/ts-rs deps)
cargo test -p demos --test roundtrip   # headless end-to-end bridge test (real JS runtime)
```

The `roundtrip` test (and the other bundle-driven tests under `examples/demos/tests/`: `demo_switch`, `devtools_roundtrip`, `home_shared_flight`) drives the JS thread directly and asserts an initial render + click round trip. **It requires the bundle to be built first** (`npm run build -w demos`); if the bundle is missing it skips (passes) with a notice. The synthetic-bundle tests (`decode_warnings`, `hot_reload`, …) stay under `crates/core/tests/`.

Lint / format / typecheck (run from repo root):

```sh
npm run lint          # eslint + tsc (all workspaces) + format:check — NOT clippy
cargo clippy --workspace --all-targets    # run separately (CI runs it as its own step)
cargo hack check -p bevy-react --each-feature --no-dev-deps --features bevy/x11   # every facade feature alone (CI; needs cargo-hack)
npm run typecheck     # tsc --noEmit across JS workspaces
npm run format        # prettier --write . && cargo fmt
npm run format:check  # CI-style check (prettier + cargo fmt --check)
npm run generate      # rewrite the generated core TS (style.ts + elements.ts)
```

`npm run lint` is JS-side only (plus `cargo fmt --check` via `format:check`); clippy is deliberately **not** in it — CI's typescript job runs `npm run lint` on a runner without Bevy's system deps, so clippy lives in the rust job as its own step. Run it yourself before handing off Rust changes.

## Architecture: the Rust↔JS bridge

The whole boundary is a dedicated **JS thread** (owns the V8 isolate, runs a `current_thread` tokio runtime) connected to the **Bevy main thread** by channels. Understanding the message flow requires reading `crates/core/src/js_thread.rs`, `crates/core/src/plugin.rs`, `crates/core/src/protocol.rs` (a directory module — `protocol/{op,props,merge,…}.rs`), and `js/src/bridge.ts` together.

**Four ops** (`crates/core/src/js_thread.rs`) form the boundary:

- `op_flush(json)` — JS→Bevy, sync. The reconciler batches a `Vec<Op>` per commit and flushes it as one JSON string; `serde_json` decodes it into `protocol::Op` (style values straight into their property types, through the thread's registry — see "the style property registry").
- `op_emit(name, value)` — JS→Bevy, sync, fire-and-forget app message.
- `op_request(id, name, value)` — JS→Bevy, sync; correlated request awaiting a reply.
- `op_next_event()` — Bevy→JS, **async** (Rust Future → JS Promise). Returns one `protocol::Outbound`.

**Channels** are created in `ReactUiPlugin::build` (`crates/core/src/plugin.rs`): crossbeam for JS→Bevy (`Vec<Op>`, `ReactMessage`, `RawRequest`), tokio mpsc for Bevy→JS (`Outbound`) and reload signals.

**`Outbound`** (`crates/core/src/protocol/outbound.rs`) is one internally-tagged enum (`uiEvent | elementEvent | event | response | animationFinished | reload`) carrying _everything_ Bevy sends to JS over a single channel. `js/src/bridge.ts`'s `runEventLoop` is a **router**: it `switch`es on the tag and dispatches the common UI events (click/pointer/scroll/wheel) and an element's own events (`elementEvent` — the handler gets the payload) to React handlers (keyed by node id + event name), named events to listeners, and responses to the awaiting promise. The reconciler→Bevy identity map is `NodeId(u32) → Entity` (`crates/core/src/bridge.rs`); node id `0` is the UI root. Requests carry their own `u64` correlation id.

The reconciler/render side lives in `js/src/` (`renderer.ts`, `mount.ts`, `bridge.ts`). The Bevy side that consumes ops and produces events: `crates/core/src/reconcile/` (`apply_js_ops`, the generic create/update paths, `collect_ui_events`), `crates/core/src/element/` + `elements/` (the registry and the core elements), and `crates/core/src/ui_map.rs` (style→`bevy_ui` component mapping).

**The JS wire is generic.** Every prop except `children`/`key`/`ref` crosses; a function-valued `onXxx` crosses as `true` and registers a JS-side handler under event `xxx`; a bigint crosses as a number. The JS runtime holds no per-key tables — per-key rules (an explicit `false`, an act-now unset) live in Rust, decoded against the node's element. Every `create` and `update` op carries `kind` **before** `props` (attributes are per element — see "the element registry"). `<canvas>` is the one kind-aware JS exception (its painter and imperative handle).

**Updates are deltas — the only form.** `commitUpdate` diffs old/new props (`buildUpdateOp` in `bridge.ts` — handlers by presence, `style` field-by-field, everything else structurally) and emits `Op::Update { props, unset, styleUnset }` carrying only changed fields; a re-render with no value changes emits **no op at all**. Rust keeps the last applied props per node (`JsBridge::props_cache`), merges each delta (`Props::merge_delta` — absent = unchanged, `unset`/`styleUnset` = reset; the style merge is per property, compare-before-set, reporting the touched properties as a `StyleDirty` bitset; attributes replace per key, compare-before-set, as an `AttrDirty` bitset), and re-runs **only the writers that read a touched property or attribute** (`apply_style_masked` in `ui_map.rs` — see below). Act-now props (`scrollTop/Left`, and act-now attributes like `value`/`draw`/`drawAppend`) are split off, never cached — an update carrying only act-now attributes is an imperative command. Event-loop consequence: op silence on an idempotent re-render is normal, so don't probe runtime liveness with a state-neutral click.

## Architecture: the style property registry (`crates/core/src/style/`)

The terms are in `CONTEXT.md`. Every style property — core included — is a `static StyleProperty<T> { name, codec, invalidate }` (struct-update defaults: `..StyleProperty::new("x")` for serde + ts-rs types, `::with_codec(name, Codec::keyword(&TABLE) | Codec::serde_as(ts) | Codec::custom(decode, ts))`), registered with `app.add_react_style(&P)` / `add_react_styles(&[..])`; the core's 74 live in `style/props/` (`CORE_STYLES` + the `CoreId` enum from one `core_styles!` list — fixed ids, so core masks are `const`). The static IS the key: `style.get(&OPACITY)` (pointer identity — declare `static`, never `const`). The store (`style/store.rs`) is sparse and decoded straight from the wire via erased-serde through the thread registry (`core_registry()` fallback); an unknown key warns `unknownStyleField`. **Behavior lives in writers** (`style/writers/`, `CORE_WRITERS` in registration order = apply order): `Writer { reads, writes: &[owns::<C>], apply: fn(&WriterCtx, &Style, &mut EntityCommands) }`, registered with `add_react_style_writer(s)`; a clash on `writes` panics, >64 writers panics, and a non-core property no writer reads is **auto-stamped** as `StyleValue<T>` (unique value type, else panic at `validate()`). **Invalidation** is declared per property (`Invalidate::Fixed(set)` or `Computed(fn(old, new, &NodeCtx))` — `opacity` and `transform` are computed; the merge records old values for computed properties only): `PAINT` → `layer::mark_content_dirty`, `PROMOTION` → `bridge.layer_dirty`. Hover/press/focus variants carry every property (their restyle re-runs the writers of the variant keys, not everything); promotion unions every state. Adding a core property = one static in `style/props/` + `CORE_STYLES` entry + a writer reading it (or an engine reading it by key), then `npm run style:generate`. `BevyStyle` TS is generated: core into the committed `js/src/generated/style.ts` (`style::ts::tests::core_style_ts_is_current` diffs it; `UPDATE_STYLE_TS=1` / `npm run style:generate` rewrites), app properties into the app's `bevy.ts` as a `declare module "bevy-react" { interface BevyStyle }` augmentation. There is no per-field JSDoc (docs live on the Rust statics). Devtools pulls its field table at install (`devtools.styleFields` request → `{ name, category, kind }`; category derived from the TS type, keyword kinds feed `warnings.ts`).

## Architecture: hot reload (React Fast Refresh)

Editing a component **preserves its `useState`/hook state** (and live animations); only non-component edits or errors fall back to a full reload. The mechanism spans three layers — read `js_thread.rs`, `js/src/hmr.ts` + `renderer.ts` + `mount.ts`, and `js/build-lib.mjs` together:

- **The isolate stays alive.** `spawn_js_thread` builds the V8 isolate once (`build_runtime`: prelude → `vendor.js` → `app.js`, all via `execute_script` — the app bundle is a classic-script IIFE, **not** an ES module, so it can be re-run). On a reload signal it does **not** rebuild: `pump` returns control to Rust, `apply_update` re-`execute_script`s the rebuilt `app.js` into the **live** context, and the next `pump` drives the refresh. Only a sync error in the new bundle triggers a full `build_runtime` rebuild. The bundle path is the **app** bundle; `vendor.js` is its sibling.
- **The React root persists.** `renderer.ts` keeps the `reconciler` + `root` module-level (they live in the never-re-executed `vendor.js`) and calls **`reconciler.injectIntoDevTools(...)`** — required, or `performReactRefresh` is a silent no-op. `mount.ts` runs `reset()` + `createContainer` only on the **first** call (guarded by `globalThis.__hmr.mounted`); a re-execution instead calls `__hmr.applyUpdate()` (→ `performReactRefresh`) and re-parks the event loop.
- **Components are instrumented.** `build-lib.mjs` runs each app source through **SWC's react-refresh transform** (`jsc.transform.react.refresh`) in an esbuild `onLoad` plugin, post-processing `$RefreshReg$` ids to be module-unique. `app.js` externalizes react/bevy-react to `globalThis.__bevyVendor` (set by `vendor.js`) so re-running it does **not** recreate the reconciler. `hmr.ts` installs the refresh runtime (`injectIntoGlobalHook`) before the reconciler is created.

Because the whole app bundle is re-executed (every component becomes a fresh function), `performReactRefresh` re-renders the tree — picking up non-component edits too — while preserving hook state for signature-stable components. Headless coverage: `crates/core/tests/hot_reload.rs` (Rust isolate-persistence) and the cold path in `examples/demos/tests/roundtrip.rs`.

## Architecture: typed, codegen-synced app messaging

Three app-level channels, all **typed in Rust and mirrored to TypeScript by codegen** (`ts-rs`). Each direction has an attribute macro (`crates/macros/src/lib.rs`), a registry resource, and a slot in the single exporter.

- **React→Bevy notify** — `#[react_message]` → `ReactPayload` (`crates/core/src/message.rs`). `emit(name, value)` routes by name, deserializes into the typed struct, and `commands.trigger`s it for observers. Register via `app.add_react_handler(observer)`.
- **React→Bevy request/response** — `#[react_request(name, response = T)]` → `ReactRequest` (`crates/core/src/request.rs`). Observed as `On<Request<T>>`; answered with `req.respond(value)`. The `Responder` is `Clone + Send`, so replies can be deferred across frames. Unknown name / malformed payload **reject** the JS promise (never hang). Register via `app.add_react_request_handler(observer)`.
- **Bevy→React events** — `#[react_event(name)]` → `ReactEvent` (`crates/core/src/event.rs`). Sent from any system via the `ReactEvents` system param (`events.send(&E)`). Register via `app.add_react_event::<E>()` so the exporter knows the type. JS subscribes with `bevy.on(name, cb)`.

### The codegen sync invariant (important)

The Rust binding structs are the **single source of truth**. `App::export_react_typescript(path)` (`crates/core/src/message.rs::render_typescript`) walks all the registries (messages, requests, events, **filters**) in one pass and writes a self-contained `bevy.ts`: per-payload type declarations, the `ReactMessages`/`ReactRequests`/`ReactEvents` maps, a `declare module "bevy-react"` block augmenting the `BevyFilters` interface with every registered filter's params type (without it the `filter` style is intentionally untyped-unusable — `FilterUse` collapses to `never`), typed `emit`/`request`/`on` wrappers, and a structured **`bevy` proxy** whose nested methods come from dotted request names (`"board.get"` → `bevy.board.get()`; a void/unit request payload → a zero-arg method).

- The example exposes this via `cargo run -p demos -- --export-bindings <path>` (a flag handled in `examples/demos/main.rs` that builds a bare `App`, runs the shared `register_react_bindings` aggregating every demo's bindings, exports, and returns without `app.run()`). The npm convenience is `npm run bevy:generate -w demos`.
- **After changing any `#[react_message]`/`#[react_request]`/`#[react_event]`/`#[react_filter]`/`#[react_morph_filter]` type — or registering/unregistering a filter — regenerate** and commit `bevy.ts`. Output is deterministic (sorted); the CI guarantee is regenerate-then-`git diff --exit-code`. `bevy.ts` is `.prettierignore`d so prettier never fights the generator.
- App code imports the typed surface from `./bevy` (e.g. `import { bevy, emit } from "./bevy"`), **not** the untyped functions from `"bevy-react"`.

## Architecture: named nodes (the Bevy escape hatch)

Every element takes a `name` prop (`<node name="hud">`): it crosses as its own wire field, is cached like any prop, and lands on the entity as a Bevy `Name` (dynamic — a delta replaces it, `unset`/`""` removes it). Rust reaches React-created entities two ways: the public `ReactNode(NodeId)` marker (every bridge entity carries it — `Query<(Entity, &Name), With<ReactNode>>`, `Added`/`RemovedComponents<ReactNode>` for lifecycle) and the `ReactNodes` **system param** (`get`/`all`/`iter`/`contains` — a hash index living on `JsBridge.names`, maintained by the op-apply path in `crates/core/src/names.rs`; `apply_js_ops` is at Bevy's 16-param cap, which is why it's a SystemParam over the bridge and not a separate resource). Order consumers `.after(ReactApplySet)` (wraps `apply_js_ops` in `Update`) for same-frame mounts. Names are **not unique** (group semantics; `get` returns the first mounted and reports a `nameAmbiguous` devtools warning). `Name` on React nodes is **bridge-owned**, like every component the bridge writes (`Node`, colors, text, `ImageNode`, `Children`…) — the `ReactNode` rustdoc carries the list. Foreign Bevy children under a React node are deliberately unmanaged: they die with the parent (recursive despawn) but are orphaned by any sibling change (the hierarchy sync `replace_children` from the shadow tree). `<surface>` binds its texture with its own `target` attribute (as does `<portal>` — a per-element namespace); `name` is identity only. Demo: "Named nodes" (`examples/demos/scenes/named_pins.rs`).

## Architecture: composited layers & filters

Some styles promote a subtree to a **composited layer** (`crates/core/src/layer.rs` + `layer/render.rs`): `opacity` on a node with children (group-alpha web semantics; opt out with `groupAlpha: false`), a non-empty `filter` chain, a `transform3d` (presence, even identity `{}`), or `cache: "always"`/`"never"`. Promotion is render-side only — layout/picking/refs/animations untouched — via a custom pass over stock `bevy_ui_render` (public seams, no fork): the subtree is captured into an offscreen texture and composited back as one quad at its stacking position. Captures are **cached** (a clean layer skips its capture pass), and translation, group alpha, and filter params are **composite-time** — animating them never re-captures. `cache: "never"` opts a subtree out: it force-promotes but re-captures every frame — and dirties every enclosing layer too — the escape hatch for pixels written outside the dirt tracking's sight (a live `<portal>` render target, an app-owned texture); time-driven _filters_ don't need it (`USES_TIME` already re-runs their passes). Captures are also **clip-independent**: ancestor clipping (scrollports/viewport) never bakes into captured pixels — a main-world interior-clip cascade (`layer/clip.rs`) feeds an extract-window `CalculatedClip` swap (`layer/render/clip.rs`, invisible to main-world systems like picking), and the ancestor clip clamps the composite quad at draw time instead (web semantics: overflow clips the filtered _result_; scrolling a layer is always a cache hit, and a layer scrolled into view is correct by construction). Offscreen layers still capture when dirty (quad draws nothing) — known cost: invisible re-captures for continuously-animated offscreen subtrees.

The `filter` style is a chain of `{ name, params }` (one object or an ordered array; order = pass order). Each resolved pass is a fullscreen WGSL pass, run capture → ping-pong textures → composite. Pass shaders `#import bevy_react::filter` (the prelude in `crates/core/src/layer/filter_prelude.wgsl` owns the bind-group contract + vertex stage), name their entry point `fragment` (`filter` is a WGSL reserved word), and follow the prelude's premultiplied-alpha rules (color ops unpremultiply around the math; blur-like resampling must not). Pass UVs span the **inflated** capture (node rect + the chain's summed outset ring); the uniforms carry that inset (`content_inset`), and the prelude's `content_uv()`/`content_rect_size()` recover the node's border box — how `gradientMap` (multi-stop linear-gradient recolor) keeps its gradient anchored to the text box when chained with `outline` (alpha-dilation ring under the content) — text-effect built-ins alongside blur/bloom/`shadow` (offset + blurred drop shadow, bloom's reuse-blur pass structure) and the color ops. A custom filter is a `#[react_filter]` params struct + a shader asset, registered with `app.add_react_filter::<T>()` — in **both** the running app and the exporter path (keep the call in the shared `register_bindings` site), or the generated typing silently diverges from runtime; then regenerate `bevy.ts` (same codegen sync invariant as above). Regular filters and morph filters are **separate families** in one registry (`ReactFilter::IS_MORPH`): custom morphs use `#[react_morph_filter]` + `app.add_react_morph_filter::<T>()` (name/shader args only), land in the generated `BevyMorphFilters` interface (regular filters land in `BevyFilters`), and the split is enforced at resolve time — a morph name in a `filter`/`backdropFilter` chain warns (`filterParams`/`backdropFilterParams`) and skips the entry, a regular name in `morphFilter` warns (`morphFilterParams`) and snaps. Pipelines are specialized per `(shader, camera target format)` and compiled async on first use, and a not-ready pass **gates** its layer (the subtree draws nothing meanwhile — a dark blink the first time a morph runs); `ReactUiPlugin::precompile_filters(PrecompileFilters { builtins, filters, morphs })` (each a `FilterSelection::{All, Names, Off}`, default `All`; `builtins` = everything the crate ships in both families, the other two = the app's `add_react_filter`/`add_react_morph_filter` registrations) warms the selected shaders plus the format-only layer pipelines (composite/mip/backdrop blit) for each camera format the first frame the render world sees it (`filters/warm.rs` builds the handle list in `Startup` from the registry's per-entry `warm_shaders` slot — identity/empty params resolved, so a defaults-less custom multi-pass filter warms pass 0 only; `layer/render/warm.rs` queues the pipelines). A wrong-partition or unknown name warns once (`precompileFilters`). The idle-morph `morph_warm` pre-specialize stays for `Names`/`Off` apps.

The `transform3d` style (`layer/transform3d.rs` + `layer/render/transform3d.rs`) applies a 3D perspective transform to the captured result at composite time — a per-quad matrix (dynamic-offset uniform, real `w` for perspective-correct interpolation, z flattened post-transform) reshapes the composite quad; animating it is composite-only dirt (never re-captures, never re-runs filter passes). Fixed field order (scale → rotateX/Y/Z → translate → self-`perspective`, around `origin`); ancestor clip clamps the transformed result fragment-side; nested transform3d flattens into the parent capture. **Picking follows the visual** (`layer/pick3d.rs`): a shared `PointerId::Custom` virtual pointer inverts the cursor through the layer's screen homography onto the untransformed layout rect, real-pointer hits on transformed members are suppressed, and `Interaction`/`RelativeCursorPosition`/cursor-icon are corrected from the virtual pointer — identity transforms keep all of it inert. `transition: { transform3d }` eases field-wise (perspective snaps at an orthographic endpoint; unsetting the whole field demotes + snaps — keep an identity `{}` when removal should ease); inline `{ animated }` wrappers drive single fields (degrees for rotations, like every rotation in the system — the 2D `rotate` binding is degrees too). Transformed quads are antialiased Chromium-style: ~1px analytic edge feather in the composite fragment (`EDGE_AA_INFLATE_PX`, quad inflated in pre-transform space), and the sampled texture of any `TRANSFORM3D`-reason layer carries a full mip chain (`layer/render/mips.rs` — downsample blit staged like filter runs, rebuilt only when level 0 rewrites, so cached/animated layers pay nothing) sampled trilinear+anisotropic for non-identity quads; while mips are stale/compiling the composite falls back to bilinear, never gates. v1 limits: nested transformed-in-transformed picks via the nearest root only; click-through _under_ the visual quad; magnified captures sample soft (1:1 capture).

**`backdropFilter`** is the fourth chain surface: same wire shape and registry as `filter`, but it filters **what is rendered behind the node** — v1: the camera's post-processed 3D frame only (UI painted beneath the node is not included) — and composites the result as an opaque quad one epsilon under the node's content quad. Mechanism (`layer/render/backdrop.rs`): a per-frame snapshot blit crop-samples the camera's main texture over the layer's (outset-inflated) capture rect inside `ui_layer_capture_pass` (the blit bind group is created **in the pass** — the ViewTarget's a/b main texture flips during PostProcess, so prepare-time binding races), then the chain runs over the snapshot with the snapshot bound as both pass-0 source and binding-3 `capture_texture`, so **every existing filter shader works unchanged** (the blit writes alpha 1.0 explicitly — opaque satisfies the premultiplied contract trivially). Everything mirrors `filter`: promotion (`PromotionReasons::BACKDROP`, presence union), a second resolver instance (`resolve_chains<BackdropInput, ResolvedBackdropChain>` — backdrop chains are **forced `always_dirty`**, the source is live), a second transition channel (`transition: { backdropFilter }`, same empty-chain snap — keep an identity entry for eased removal), inline `{ animated }` param wrappers, and `backdropFilter*` diag kinds. The frosted quad covers the node's border box (shrunk out of the blur-outset ring) and **respects `borderRadius`**: the composite fragment masks coverage with a rounded-box SDF ported from bevy_ui's own `ui.wgsl` (same layout-resolved `ComputedNode.border_radius` radii, same `saturate(0.5 − sd)` antialias convention), so the frost edge coincides with the node's painted rounded background; all-zero radii disable the term exactly (the `edge_feather` select pattern — content quads stay pixel-identical). Costs and v1 limits: snapshot + chain re-run every frame (the node's own capture still caches); the backdrop ignores `transform3d` (axis-aligned); a backdrop layer nested inside another promoted layer forces the whole enclosing chain to re-capture every frame (live pixels defeat ancestor caching by design); gating is graceful (a not-ready backdrop shows the unfiltered frame, never an invisible subtree).

**`morphFilter`** is the view-transition surface: `morphFilter: { key, name, params }` on a node freezes its previous rendered appearance when `key` changes (string|number; only a change triggers) and blends frozen → live content with the named two-input filter, driven by an engine-owned `progress` eased 0→1. The one channel with **built-in default timing** (300ms ease-in-out — `transition: { morphFilter }` overrides); first mount/no-capture snaps; a mid-flight key change freezes the in-flight blend and restarts (always smooth); unset demotes + snaps. Presence force-promotes (`PromotionReasons::MORPH` — a cached capture must exist to freeze). Mechanism: the transition channel (`transition/channels.rs::MorphChannel`) bumps `MorphState.freeze_seq` + pushes capture dirt; render-side (`layer/render/morph.rs`) the freeze **steals** the old texture (the capture, or an interrupted morph's blend — no blit/copy, survives reallocs) into `MorphSlot.snapshot` in `prepare_layer_textures`, and a per-frame blend pass writes a dedicated `blend` texture (binding 0 = live capture "to", binding 3 = snapshot "from", engine data in the **reserved param tail**: `params[7].x` = progress, `params[6]` spare — shader authors use the prelude's `morph_progress()`/`morph_sample_from()`/`morph_sample_to()`). A regular `filter` chain composes on top (morph first: the chain's pass 0 sources the blend); a morph-only composite samples the blend, gated like the filter gate. The frozen snapshot is **layout-anchored**: the blend stretches it onto the node's current capture rect (plain 0..1 UV over both textures), so scrolling or moving the node mid-flight carries both images together and never touches the capture rect (a mid-morph scroll stays a cache hit); a size change across the swap stretches the old appearance — handling that gracefully is the app's responsibility. Settle is invisible by the **progress-1 identity contract**: at `progress == 1.0` a morph shader must output exactly the source sample — the settle frame renders at 1.0 before the pass drops. Morph filters are their **own family** (registered via `#[react_morph_filter]` + `add_react_morph_filter`, typed by `BevyMorphFilters`): a regular filter name in `morphFilter` warns (`morphFilterParams`) + snaps. v1 caps: a morph filter must resolve to exactly ONE pass with user params ≤ 6 vec4s; built-ins `crossfade`, `linearWipe { angle, softness }`, and `pixelize`; morph _param_ `{ animated }` bindings ride the animation side (`morphFilter.<param>`, park nothing — progress is engine-owned). Known v1 limit: a morph-only layer under `transform3d` samples bilinear (no mips on the blend). **Empty layers are valid transparent captures**: a promoted layer whose subtree paints nothing still runs its (clear-only) capture pass and marks `content_valid`, and a MORPHING item-less layer's composite quad falls back to the root's own stacking position (`ExtractedLayer::fallback_sort_key`) — so the **empty-carrier idiom** works with no placeholder drawable: keep a nothing-painting carrier mounted, toggle its content in the same commit as the key flip, and the morph blends from/to genuinely empty pixels (the carrier must have rendered ≥1 frame before the first flip — a same-commit mount+flip adopts the key silently, the mount rule).

Runtime behavior worth knowing: `transition: { filter }` eases matching chains param-wise and fades trailing built-in adds/removes through identity values, but easing **to an empty chain snaps** (unset `filter` demotes the layer — there is no resolved chain left to write into), so keep an identity entry in the base style (e.g. `{ name: "blur", params: { radius: 0 } }`) when removal should fade. An inline `{ animated: sv }` wrapper on a param drives it per frame, values in wire units (px lengths, degree angles); the wrapper's optional `seed` is the static value the resolver decodes in its place (size it for the animation's range when the param feeds the capture outset, e.g. a blur radius). A filter pass whose shader fails to compile gates its layer's composite — the subtree is **invisible** until fixed — and warns naming the layer + the error (immediately on a hard compile error; after a hang threshold for a never-ready pipeline). The devtools Layers tab lists promoted layers with their chains and live param values. Gradients ease too: `transition: { backgroundGradient | borderGradient }` eases **strictly-matching** structures (same kind, stop count, colorSpace, per-stop position presence, radial shape variant) stop-wise — sRGB stop colors like `backgroundColor`, numeric long-way angles, same-unit `Val` lerp with per-leaf snap — and any structural mismatch **snaps immediately**, silently (deliberately unlike filter's 0.5-crossfade discrete swap); setting/unsetting a gradient snaps silently, so fade via transparent stops in the base style when appear/removal should ease. Gradient leaves also accept inline `{ animated }` wrappers (degree/px wire units; the apply stage rebuilds from the `GradientTargets` stamp, riding the same writers): any binding parks that surface's whole transition channel, and mixing a binding with a transition spec on one surface warns (`gradientTransition`). `transition` channels are **explicit-only** — the `all` shorthand was removed (morphFilter keeps its built-in 300ms default). Filter `Angle` params lerp numerically (no shortest-arc wrapping — 350°→10° goes the long way). `transition: { borderRadius }` eases the corner radii per corner (same-unit corners interpolate, a corner changing unit snaps alone; unset eases to square) — the value lands on `Node.border_radius` (bevy keeps radii on `Node`), so like `size` every eased frame is a relayout, and the drive pushes content dirt (the radius is outside the layer geometry hash); a uniform `borderRadius: { animated }` binding (one px value for all corners — the `borderColor` precedent, no per-corner wrappers) parks the channel and is excluded from `has_node_props` (it never moves the rect).

**`transition: { layout }`** is the FLIP channel (`crates/core/src/transition/layout.rs`; the rules in the `LayoutChannel::drive` doc, the terms in `CONTEXT.md`). Operationally: `drive_layout_transitions` runs in `PostUpdate` `after(UiSystems::Layout)`, `before(UiSystems::PostLayout)` and before `sync_layer_geometry`, measures taffy's local rect via `UiSurface::get_layout(entity, use_rounding)` — rounded or not per the node's effective `LayoutConfig`, exactly as bevy displayed it — and composes the delta into the animating subtrees' **`UiGlobalTransform`** (never `UiTransform` / `ComputedNode`); bevy re-derives pristine globals next frame, a settled node writes nothing, and the layer geometry gate (`Changed<UiGlobalTransform>`) repaints cached enclosing layers for free. Two couplings to keep: the channel's ownership gate (`RectWriter`) — a `{ animated }` `Node`-field binding (`AnimatedBindings::has_node_props`) makes it adopt outright, while the node's **own** `size` channel (`TransitionState::size_in_flight`, generated from the `size` rows of `with_input_channels!`, plus one grace frame for the settle step) makes it adopt only the re-flow the size channel's own per-frame step explains (`SIZE_STEP_SLACK` × `LayoutChannel::note_own_size` — the channel's step, not the measured rect's, which a flex squeeze snaps) and ease any larger jump translate-only with a target that follows the live rect, so `size` + `layout` on one node compose (a flex-direction swap under a size flight still glides) — and a promoted root's capture window is the border box's **transformed AABB** (`sync_layer_geometry`), since the FLIP scale lands in its global. The FLIP scale is the node's own — children compose from the translated-but-unscaled frame, so a resizing container eases its box with crisp content (a `<text>`/`<image>` node's own paint does scale) — but its surroundings snap; a container that must re-flow its siblings uses the real-layout `size` channel with `layout` on the children (the demo pairing). Real-layout size animation (the shared size flight, `transition: { size }`, a bound `Node` field) steps in whole pixels under bevy's layout rounding, and everything re-flowing around it hops — the `layoutRounding: false` style (→ bevy's `LayoutConfig`, inherited, its own writer, a component write with no relayout) lays a subtree out at fractional px, at the price of soft edges/blurred text at rest — set it on the parent that lays out the animated node and its neighbours (inherits downward only, restarts at `<surface>`/`<root>`; `LayoutConfig` is bridge-owned). Demo: "Layout rounding". Known v1 limit: a rect driven continuously by something the engine can't attribute (an ancestor's `size` ease, a window-resize drag) re-arms every frame — it lags, then catches up. Headless coverage: `transition/layout_tests.rs::layout_app` runs bevy's real `ui_layout_system` (the harness mirrors bevy_ui's own) — reuse it for anything that needs real layout.

**Shared elements** (`sharedTag` prop + `transition: { sharedElement }`; `crates/core/src/shared_tags.rs` pairs, `crates/core/src/transition/shared.rs` seeds, the terms in `CONTEXT.md`). React has no reparenting, so a node that "moves" between parents/screens is an unmount + mount; the tag is the identity and **the commit is the trigger** (no imperative API). Pairing is a Rust pre-pass in `apply_js_ops` (only the shadow tree knows a removed subtree's contents — a screen swap emits ONE `Remove`), gated on the tag index being non-empty: same tag, same element kind (every node's kind is recorded in `SharedTags` since a later delta can add a tag), same UI root, same batch; the first mounted match seeds every incoming node with the tag, silently (no diag). Mechanics to keep: the outgoing entity is read by a command queued **before** any op's commands (its despawn is deferred like every command) into `PendingSharedSeeds`, and stamped as a `SharedSeed` by a command queued **after** the loop — `apply_js_ops` is at the 16-param cap, so both are `commands.queue` closures, not new system params; `stamp_pending` drops the seed unless the incoming style has a `sharedElement` spec (explicit-only, no default). The engine side is "seeded first sight": `drive_transitions` overlays the seed's value-channel currents (size rows excluded) so each block's ordinary retarget path arms from there, with `or_shared` falling back to the `sharedElement` spec while `TransitionState::shared.active`; the rect is parked for `drive_layout_transitions`, which converts it into the parent's layout space off this frame's pristine globals, seeds the layout channel (`LayoutChannel::seed_shared` — seed frame shows the seed rect via FLIP scale — with `ComputedNode.border_radius` divided out by that scale for the frame, or a seeded circle reads as a rounded square; bevy rewrites it from `Node` next frame — then translate-only with a moving target while the size flies; **both ends stay root-space anchored**: `SharedFlight::origin` and `SharedFlight::destination` are re-expressed in the parent's frame every flight frame (`rebase_shared` / the target), so a parent the size flight re-flows — a centered container — never drags the take-off point along, and the position eases toward where the node will SETTLE rather than chasing the live rect the flight's own eased size is dragging around — chasing it is a lerp toward a target itself linear in progress, i.e. quadratic, and the flight visibly bows. The destination is captured on the seed frame, the one frame the natural rect is measurable), and arms the measured-px size flight (`arm_shared_size` / `drive_shared_size`: `Node.width/height` ease in logical px from the seed's size to the natural size measured at first layout, settle restores the authored `Length`) — the flight also **takes over the node's `flexGrow`/`flexShrink`** for its duration (restored on settle), since a flex item's main-axis size is its basis adjusted by grow/shrink: without that, a flight into a SMALLER container (a panel collapsing back into its tile) has its flown px shrunk straight back and that axis snaps a frame after the seed while the cross axis eases on. Nested shared flights (a tagged node inside a tagged node) each fly their own straight root-space line: a shared flight's delta is **root-anchored** (`LayoutDelta::root_anchored` — the walk composes it against the parent's _pristine_ frame, never the shown one, or the ancestor's delta lands twice), and a flight that settles while an ancestor still animates parks at its destination (`SharedMode::Landed`, gated by last frame's animating set) until the ancestor is done. v1 limits: two-commit mounts (Suspense) don't pair; the flight is clipped by the new parent like any layout transition; no completion callback; the natural rect — size AND destination — is measured once, on the seed frame, and afterwards only motion the flight's own size (or a flying ancestor's) cannot explain moves the ends (`SharedReflow` in `transition/shared.rs`: a frame-1 least-norm fit of position-per-size-px, deviation = external, both ends shift together so a scroll under the flight scroll-locks it; landing is exact whatever the fit reads, a wrong fit only bends the path) — an ancestor's plain `size` ease or a `Node` binding re-flowing the node reads as external and is followed, not attributed; a flight that changes the node's real layout size re-flows its ancestors, so the flying node wants a parent that holds constant space (a fixed slot). Headless coverage: `shared_tags.rs` tests (pairing rules + end-to-end color seed), `transition/layout_tests.rs` (`shared_seed_*`).

## Architecture: the element registry (`crates/core/src/element/`)

The terms are in `CONTEXT.md` ("Elements"). Every element kind — the core's included — is a `static Element { name, flags, attrs, required, common, writers, suppress, events, default_style, spawn, ts_ref }` (struct-update defaults `..Element::new("x")`), registered with `app.add_react_element(s)` (core: `CORE_ELEMENTS` in `crates/core/src/elements/`). Registering an element registers its attributes, writers, and events. Resolved against the style registry into an `ElementInfo` (`element/registry.rs`: attribute/event lookup, per-element writer tables).

- **Attributes** are `static Attribute<T> { name, codec, event, invalidate, typed, animated }` — the static is the typed key (`ctx.attr(&SRC)`, `props.attrs.get(&SRC)`). Only element-specific props are attributes; the props every element shares (`name`, `sharedTag`, the style variants, `onClick`/`onPointer*`, `onScroll`/`scrollTop/Left/Step`, `onWheel`) stay fixed `Props` fields, grouped by `Common` — an element declares the groups that apply (a common prop outside them warns `propIgnored` at decode). **Per-element namespace**: two elements may declare one name with different types. The op decoder opens a `DecodeScope` when an op's `kind` key streams by (the runtime emits it before `props`), so `Props` decode resolves keys against that element; an unknown key warns `unknownProp`. `event: true` = act-now (split off, never retained); `invalidate: PAINT` pushes layer content dirt; `typed: false` keeps a wire-only attribute out of the JSX types; `animated: Some(AttrBinding { domain, .. })` publishes `{ animated }` bindings as `AnimatableProperty::Ext { domain, name: <attr> }` — the binding picks the published kind (`DrivenValue::Scalar`, or `DrivenValue::Color` for an `interpolateColor`), so an attribute of any value type can animate.
- **Behavior lives in writers** (the style registry's `Writer`, with an `attrs` list): global style writers run on every styled element (masked by the element's table), the element's own writers run only there and may read attributes and style properties. A component an element writer `writes` masks off the global writer writing it on that element; `suppress` opts out explicitly; a style property only masked-off writers read warns `styleIgnored`. There is **no per-element update function**: create = the `spawn` hook (born-with components, one bundle via `SpawnCtx::spawn`) + the fresh writers + the common stamps; update = merge + the writers reading what changed (style or attribute) + the dirty common stamps — one path for every kind (`reconcile/{create,update}.rs`). The interaction restyle and the promotion flip run element writers too (an `<image>`'s tint re-folds a hover opacity through its writer).
- **Flags and defaults instead of kind checks**: `ElementFlags { node_less, owns_image, layer_ineligible, detached, text: TextRole, pick_ignore }`; `default_style` is the UA stylesheet under the user's style (`<button>` → `focusPolicy: "block"`, `<root>`/`<surface>` fill their target; `StyleVariants.base` is the effective style). `detached` = the op path never attaches the node in the Bevy hierarchy but records its React parent (`bridge.detached` + `detached_parent`; removing an ancestor despawns it) — detached roots and `<anchor>` overlays (parented under the anchor crate's own `AnchorLayer` root).
- **Element events**: `static ElementEvent<T>` listed in `events`; the handler prop is `on` + the capitalized name, its argument the payload (`()` = no argument). Sent with the `ElementEvents` system param, gated on the node's `EventSubscriptions` (kept in sync with its handler props) unless `.unconditional()` (the canvas `resize` the JS handle always consumes) → `Outbound::ElementEvent`.
- **Generated JSX typing**: `element/ts.rs` builds a props interface per element (`Bevy<Kind>Props`, from the `Common` group interfaces in `js/src/jsx.d.ts`, `style`, the typed attributes, the events, `ref`, `children`) — the core's into the committed `js/src/generated/elements.ts` (`element::ts::tests::core_element_ts_is_current` diffs it; `npm run elements:generate` rewrites), an app's feature elements into its `bevy.ts` as a `declare module "bevy-react" { interface BevyIntrinsicElements }` augmentation (so after adding/moving an element or changing an attribute codec: regenerate both). Both runtimes' `JSX.IntrinsicElements` extend `BevyIntrinsicElements`.
- **The extension contract** (`bevy_react_core::ext` + `element` + `style` + `raster`): `ExtRegistry` (elements + style registry) reaches serde through a **thread-local scope** — the native JS thread installs it on its first flush from the `ExtRegistrySlot` handoff (empty at `ReactUiPlugin::build`, filled in `finish` and again in `Startup` for `App::update`-driven harnesses; `op_flush` blocks on it, a bounded wait), the web host from the same slot, the headless harness from the app; no process globals. An unregistered kind mounts as a plain node and reports one `featureMissing` naming the `bevy-react` cargo feature and plugin from the core's `KNOWN_FEATURES` table (the only place the core names a feature; the facade's tests pin it against its features and group). Contract components: `ElementFlags`, `EventLocalPos` (an element-defined pointer coordinate — the core stamps the slot on node-less elements with handlers), `LiveTexture`, `DrivenExtValues` (the animation engine's publish slot for `Ext` bindings, consumed after `AnimationSet::Apply` — `get` answers scalars, `get_color` sRGB colors, `value` either; the consumer validates a kind its field can't take; a feature runs its own park rule via `AnimatedBindings::has_ext_domain`). `VirtualPointers` (resource): a feature's picking pointer over UI the window cursor can't reach (the surface crate's in-world pointer) — the core turns its picking events into the common UI events (`reconcile/virtual_events.rs`) and its hover feeds the cursor. Engine primitives: `transition::{Channel, ChannelTransition}`, `layer::LayerContentDirt`, `raster` (pixmap cache + upload, `meet_transform`, `clamp_physical_size`, `parse_css_color`, `blank_image`, `pointer_physical_position`), `render_target` (named textures + `TargetView`).
- **Ordering by sets, never by function names**: `PickRefineSet` (PreUpdate), `InteractionSyncSet` (Update: synthesize `Interaction`/`EventLocalPos` before styling and the collectors), `ElementOverrideSet` (Update: override this frame's driven values — the anchor projection), `ElementRasterSet` (Update: repaint an element-owned texture after the op drain, the animation apply, and the transition drive), `MeasureStampSet` (PostUpdate), plus `ReactApplySet`. A feature spawning/despawning cameras orders against bevy's `CheckVisibility`/`UpdateDirectionalLightCascades` itself (see the surface crate).
- **Diag keeps `NodeId`**: a feature attributes warnings by reading the entity's `ReactNode`.
- **Test harness**: the core's `test_util` feature exports `bevy_react_core::test_util` (`op_app_with(setup)`, kind-aware `create`/`update` op builders, `JsBridge`, the diag helpers, `animation_apply()`, the `shared_*` value mutators); decode bare props with `Props::decode_for(kind, json)`. Feature crates' op-path tests dev-depend on it.

## Architecture: the plugin group & cargo features (`crates/bevy-react/`)

The facade is the crate apps depend on: `pub use bevy_react_core::*` at its root (every core path is `bevy_react::<same path>`), each feature crate as a module behind a cargo feature (`bevy_react::{anchor,canvas,portal,surface}`; `bevy_react::svg` **merges** the core's file-mode `svg` module with the JSX crate), and `bevy_react::prelude`. Features: `svg`/`anchor`/`canvas`/`portal`/`surface` (optional deps), `devtools` (core + the svg/portal/surface mirrors, `?`-weak), `custom_cursor` (core → `bevy/custom_cursor`, which pulls `bevy_winit` — needs `bevy/x11`/`wayland` on Linux, hence `--features bevy/x11` in standalone checks and docs.rs; not a core default so `cargo test -p bevy_react_core` stays winit-free), `svg_text`; `default` = all but `svg_text`. **`ReactPlugins`** (`plugins.rs`) is a unit `PluginGroup`: `ReactUiPlugin::default()` (`ReactUiPlugin::DEFAULT_BUNDLE` = `ui/dist/app.js`, cwd-relative) then each compiled-in feature plugin; members are order-independent (feature plugins only warn in `finish` without the bridge; a custom filter shadows a built-in in either order). **`ReactPlugins::register_bindings(app)`** is the exporter-side twin (elements only, same `cfg` list) — keep both lists and the core's `KNOWN_FEATURES` in step; the facade tests (`known_features_match_the_feature_crates`, …) fail otherwise. Adding a feature crate = its crate + a facade feature/dep/module/prelude line + a group and `register_bindings` row + a `KNOWN_FEATURES` hint + the CI `cargo hack` covers it.

## Architecture: SVG (files in core, JSX shapes in `bevy_react_svg`)

Two web-faithful doors, one CPU raster discipline. **File mode stays in core** (`crates/core/src/svg/`): an `<image src="x.svg">` is extension-detected and re-rasterized per node at laid-out size × DPI (usvg parses once into an `SvgDocument` asset; resvg renders — resvg IS tiny-skia underneath; layout measures from the file's intrinsic size via a `ContentSize` stamp, decoupled from the re-rastered texture; `SvgSurface` is the file-mode component). SVG `<text>` support in files is behind the off-by-default `svg_text` cargo feature (pulls fontdb). **The JSX `<svg>` element is the `bevy_react_svg` crate** (`crates/svg/src/`, `SvgPlugin`; without it an `<svg>` mounts as a plain node with a `featureMissing` warning): the 8 shape intrinsics (`circle`/`rect`/`path`/`g`/…) are **Node-less bridge entities** (`ElementFlags::NODE_LESS`, the `textSpan` precedent) whose SVG attributes are ordinary per-element attributes (`crates/svg/src/attrs.rs`, one static each; every shape lists its own subset; the shared `SHAPE_WRITER` assembles them into `SvgShape.attrs`; `viewBox` is the root's) and paint depth-first via `paint.rs` into the root's `SvgJsxSurface` (`surface.rs`; no `viewBox` = logical-px space). Per-shape pointer events: `pick.rs` refines the svg node's `PointerHits` into the topmost painted shape (shapes are spawned with a pass-through `Pickable` — bevy's hover map treats an absent one as blocking, which would hide the svg root and its ancestors, e.g. an enclosing `<button>`, from hover/press/click; pinned in `pick/hover_tests.rs`) (kurbo hit-testing in `hit.rs` mirrors the painter's geometry — a parity test pins the two backends); `interact.rs` synthesizes `Interaction`/`RelativeCursorPosition`/`EventLocalPos`, and events carry **SVG user-space coords**. Numeric attrs accept `{ animated }` bindings (published by the engine as `Ext { domain: "shape", name: <attr> }`, written into the wrapper's **seed slot** by `animate.rs`) and a `transition` prop on the shape eases static changes (`transition.rs`, the crate's own system on the core's `Channel`, state-owned-current; any shape-attr binding parks that shape's whole channel). **Write order is the invariant**: op merge → animation publish → the crate's consumer + transition drive → raster read — the crate's systems order by the contract's sets, each edge pinned by a named same-frame test (`raster_tests.rs`). All re-raster dirt derives from `Changed<SvgShape>`/`Changed<Children>`/`RemovedComponents<Children>` — every writer is compare-before-write, so an idle frame ticks nothing.

## Architecture: `imageRendering` (raster resampling)

`imageRendering: "auto" | "bilinear" | "trilinear" | "nearest"` (`crates/core/src/image_rendering.rs`, the terms in `CONTEXT.md`) fixes large images drawn small: bevy loads a PNG with ONE mip level and samples `ImageNode`s with the **asset's** sampler (bind group cached per `AssetId`), so the mode has to change an asset. It never changes the source: an explicit mode binds the node to a **variant asset** per `(source, mode)` — cloned, sampler set, `trilinear` gets a CPU 2×2 box pyramid (`image_rendering/pyramid.rs`: linear light, alpha-weighted, `Rgba8Unorm(Srgb)` only) built on `AsyncComputeTaskPool` with the node staying on its source until it lands (no interim upload; a source modified mid-build is re-derived when it lands, never cancelled) — shared by every node asking for the pair, refcounted, dropped with its last user, rebuilt in place on source `Modified`, and only made when the source doesn't already satisfy the mode (`bilinear` on a plain PNG = no copy). `auto` is passive (no write). Mechanics: the `IMAGE_RENDERING` writer stamps `ImageRenderingMode` (content dirt); `bind_image_rendering` runs after every `ImageNode` handle writer (op drain, interaction restyle, `bind_background_textures`) and re-points on `Changed<ImageNode>`/mode — every handle write pushes layer content dirt — recognizing its own repoint echo through the variant→key reverse map (never a variant of a variant) and skipping the re-plan (and re-warn) when source+mode are unchanged (tint writes); a not-yet-loaded source is retried per frame (its old binding released first). "Satisfies" reads the host's real `ImagePlugin::default_sampler` (`ImageVariants::from_app`). Live textures (`RENDER_ATTACHMENT`, canvas, svg, `<portal>`/`{ texture }` bindings — their own systems rewrite the handle) are never copied **or written** (an in-place `Modified` re-uploads the CPU buffer over the GPU target): every explicit mode is refused there with one `imageRendering` diag warning, as are data-less sources. Compositing is untouched by design (non-3D layer composites are 1:1 blits; `transform3d` already mips). Headless coverage: `image_rendering/tests.rs` (two modes/one file, sharing, refcount drop, reload, live targets), `pyramid::tests` (pixel-exact levels).

## Conventions & gotchas

- **Bevy 0.19**, Rust **edition 2024**. The core uses `extern crate self as bevy_react_core` (and the facade `extern crate self as bevy_react`) so the macros' paths resolve inside each crate's own tests. Embedded shader assets are addressed as `embedded://bevy_react_core/...` (the crate name); the WGSL import path `bevy_react::filter` is the prelude's own `#define_import_path` and did not change.
- Macro-default names lowercase the **first letter** of the struct ident (`Count` → `"count"`); override with `name = "..."`. Dotted names (`"board.get"`) only make sense as explicit overrides and drive the nested proxy.
- `ts-rs` maps Rust integers to TS `number` (precision loss above 2^53 for `i64`/`u64`/`usize`). Newtype/unit structs flatten: `struct Count(usize)` → `type Count = number`, unit structs inline to `null`.
- The `#[react_*]` macros resolve the crate they expand against from the **caller's manifest** (`crates/macros/src/krate.rs`, via `proc-macro-crate`): `::bevy_react` when `bevy-react` is a dependency, else `::bevy_react_core` (the feature crates, the core itself). They reach `serde`, `ts-rs`, and `bevy` through the core's `#[doc(hidden)] __private` re-exports (`#[serde(crate = …)]`/`#[ts(crate = …)]`), so a caller needs none of them directly — only for nested payload types it derives `Serialize`/`TS` on itself (why `demos` keeps both). ts-rs 10's serde-compat parser warns on `serde(crate)`, so core enables ts-rs's `no-serde-warnings` (globally, by feature unification) until a ts-rs upgrade (12 parses it).
- **Bevy features are explicit and minimal.** The workspace `bevy` dependency has `default-features = false`; each library crate lists exactly the bevy features its code references (plus, in core, `ui_picking`/`default_font`/`system_clipboard`, which bevy-react needs at runtime) — cargo unifies features, so a library's list decides what the app's `DefaultPlugins` contains. Using a bevy API from a feature not in the crate's list fails `cargo hack` (CI) even though the workspace build (examples = full bevy) compiles: add it to that crate's list. Log with `tracing::{info,warn,…}!` (fully qualified, as the code does) — never `bevy::log` or the bevy prelude's log macros (they'd force `bevy_log`/`LogPlugin` on apps). The internal crates' workspace entries are `default-features = false` too; a member opts into what it needs (a feature crate leaving core's defaults on would switch `devtools` back on under a facade build that turned it off).
- The example UI lives in `examples/demos/ui` (the dir is `ui`, not `app`); the per-demo React components are under `ui/src/demos/`. It bundles with esbuild (`build` script in its `package.json`) to a single ESM file that `ReactUiPlugin` loads. The Rust side is the `demos` package (`examples/demos/Cargo.toml`, `cargo run -p demos`); its `AssetPlugin.file_path` is `../assets` relative to that manifest.
- The `animations` and `filters` modules each **own their wire types** (`AnimatedBindings`, `FilterChain`/`FilterUse`); consumers import them from the owning module — `protocol` re-exports nothing. Element-owned wire types (the canvas's `DrawCmd`, svg's path/paint types, the image's `ImageMode`) never appear in `Props` at all: they are attribute value types, decoded by the element's attribute codecs into `Props.attrs`. `filters` additionally owns the `FilterRegistry` + built-ins, param packing (`ParamSlot`, no-straddle rule), and the resolve/interpolation primitives (`resolve_filter_chains`, `lerp_packed_params`). The dependency direction is module-level convention: the bridge machinery (`protocol`/`reconcile`/`ui_map`) reaches into `crate::animations`/`crate::filters`/`crate::element` — never the reverse — so adding an animation driver, filter, or element is a change in that module (or crate), not the bridge. (`layer::render` consumes `filters`' resolved chains; the filter resolve system reads `layer`'s promotion markers — that pair is deliberately coupled.)
- **Invalid-value warnings feed devtools — and `diag` is the only logger.** Every fall-back site reports through `crates/core/src/diag.rs`, which emits the terminal `warn!` itself (`diag::log_warn`, every build, deduped once per distinct `(kind, value, message)` per process — never add a site-level `warn!` next to a report, and never report per frame expecting the log to throttle beyond that) and, in `devtools`+debug builds, the structured mirror so the inspector can flag the offending row: serde-boundary fallbacks call `protocol::decode_warn(kind, value, msg)` (node id attributed per op by `protocol::OpBatch`, drained by the bridge tap via `op_take_decode_warnings`), apply-time parses call `diag::report` under a `diag::node_scope` (drained each frame → `devtools.warning` event, deduped). A new warn site's `kind` must appear in `js/src/devtools/warnings.ts` `KIND_FIELDS` — `devtools/js_tables.rs::js_warning_kind_table_covers_known_kinds` guards the list.
- **`<canvas>` is web-faithful retained pixels** (`bevy_react_canvas`). `CanvasSurface` keeps a persistent premultiplied pixmap plus persistent raster state (styles + current path survive across batches); paint **accumulates**. Two write paths, both act-now attributes: `draw` (clear + replay) and `drawAppend` (append — the imperative path behind `<canvas ref>` → `getContext()`, whose commands batch on a microtask and flush as an ordinary update op outside React commits; wire-only, untyped). A layout resize **clears** the surface (HTML width/height-set semantics) and `collect_canvas_resize_events` sends the `resize` element event with the new logical size — `.unconditional()`, not gated on `onResize`: `bridge.ts` needs it to update the handle's `width`/`height` and to auto-replay a stored declarative painter (leading `Clear` + re-recorded list). The canvas JS runtime (`js/src/canvas.ts`, the handle) stays in the `bevy-react` npm package. Headless coverage: `roundtrip.rs::canvas_resize_replay_round_trip`.

### Screenshotting the demos app (visual verification)

To see a demo rendered — to verify a visual change or refresh a screenshot — use the example's built-in `--shoot` mode, **not** OS screen capture (`import`/`grim`/`scrot`/`xdotool`). Screen-grabbing grabs the wrong window on a shared/occluded desktop, and an occluded window's swapchain reads back as 1×1.

```sh
npm run build -w demos   # build the bundle first (shoot mode disables hot reload)
cargo run -p demos -- --shoot "<portal>" out.png [settle_secs] [--size WxH]
```

- `--size WxH` (default `1280x832`, anywhere after `--shoot`) sets the logical resolution of the window and the capture — `--size 360x640` / `390x844` are how the **compact shell** (`< 720px` wide: top bar + overlay nav drawer
- The first arg is the demo's **left-nav label** (e.g. `"<portal>"`, `"<canvas>"`, `"Backdrop filters"`). The tool navigates the React gallery to it, waits `settle_secs` (default `3`) for the demo + its 3D scene to settle, captures, and exits on its own.
- It renders the whole app (3D scene + React UI) into an **offscreen `Image`** — the main `IsDefaultUiCamera` camera is re-pointed at it — and captures with Bevy's in-process `Screenshot::image(...)` + `save_to_disk`, so the result is independent of window focus/occlusion/surface (output is `--size`, default 1280×832). Still needs an X11 display present.
- Implementation: `examples/demos/screenshot.rs` (the `Shoot` state machine + camera redirect). Navigation rides a `debug.selectDemo` `#[react_event]` that `examples/demos/ui/src/App.tsx` subscribes to (`findDemoByLabel`); the `--shoot` flag is parsed and wired in `examples/demos/main.rs`. After changing the event type, regenerate `bevy.ts` like any other binding.
