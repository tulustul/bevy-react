# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

`bevy-react` drives **`bevy_ui` from a React app** running on an embedded V8 (deno_core) runtime. It is a **Rust crate + JS package** (one repo) plus an example app. React renders through a custom reconciler that emits UI-mutation ops; Rust applies them to the Bevy ECS; interactions and app-level messages flow back.

This is a virtual Cargo workspace with two crates under `crates/`: `core` (the `bevy-react` lib) and `macros` (the `bevy-react-macros` proc-macro crate). The canvas rasterizer, SVG subsystem, animation engine, and portal/surface host elements are public modules of `core` (`crates/core/src/{canvas,svg,animations,portal.rs,surface.rs}`). It is **also** an npm workspace (root `package.json` with members `js` and `examples/demos/ui`). The two halves are developed together. The example (`examples/`) and the JS runtime (`js/`) stay at the repo root; `core` declares the `demos` example via an explicit `[[example]] path`.

The example (`examples/demos`) is a gallery: a left-nav switches between demos, and React drives the active 3D scene with `bevy.selectScene(id)` (or `null` for an empty viewport). The three scenes each live under `examples/demos/scenes/` as a **separate Bevy plugin**: `cubes.rs` (cubes driven by `emit`), `bouncing_ball.rs` (one ball that both pushes Bevy→React events as toasts and answers request/response polls, and owns its own ball physics), and `crowded_cubes.rs` (crowded cubes with world-anchored badges). Only one scene runs at a time: React `emit`s the selection, and a `States` enum (`Scene` in `examples/demos/scene.rs`, variants `None | Cubes | BouncingBall | CrowdedCubes`) gates each scene's systems, with `DespawnOnExit(Scene::…)` scoping its entities. The shared 3D camera (auto-orbit + drag + zoom) is bundled as `CameraPlugin` in `examples/demos/camera.rs`.

## Commands

Build / run the example (this is the main way to see it working):

```sh
npm install                          # once
npm run build -w demos           # build the React bundles — REQUIRED before running
cargo run -p bevy-react --example demos   # run the Bevy app (needs a GPU/window)
npm run watch -w demos           # rebuild app bundle on change → React Fast Refresh
```

The build (`examples/demos/ui/build.mjs`, via `bevy-react/build-lib`) emits **two**
bundles into `dist/`: `vendor.js` (react + react-reconciler + the bevy-react runtime,
loaded into the isolate once and never re-run) and `app.js` (the app's own components,
an IIFE re-executed on each edit). Editing a component preserves its `useState`/hook
state — see "Hot reload: React Fast Refresh" below.

Tests:

```sh
cargo test                           # all Rust tests (whole workspace)
cargo test -p bevy-react --lib       # just the core library unit tests
cargo test -p bevy-react --lib ts_codegen::tests::exports_typescript   # a single test by path
cargo test -p bevy-react --test roundtrip   # headless end-to-end bridge test (real JS runtime)
```

The `roundtrip` test drives the JS thread directly and asserts an initial render + click round trip. **It requires the bundle to be built first** (`npm run build -w demos`); if the bundle is missing it skips (passes) with a notice.

Lint / format / typecheck (run from repo root):

```sh
npm run lint          # eslint + tsc (all workspaces) + format:check — NOT clippy
cargo clippy --workspace --all-targets    # run separately (CI runs it as its own step)
npm run typecheck     # tsc --noEmit across JS workspaces
npm run format        # prettier --write . && cargo fmt
npm run format:check  # CI-style check (prettier + cargo fmt --check)
```

`npm run lint` is JS-side only (plus `cargo fmt --check` via `format:check`); clippy is deliberately **not** in it — CI's typescript job runs `npm run lint` on a runner without Bevy's system deps, so clippy lives in the rust job as its own step. Run it yourself before handing off Rust changes.

## Architecture: the Rust↔JS bridge

The whole boundary is a dedicated **JS thread** (owns the V8 isolate, runs a `current_thread` tokio runtime) connected to the **Bevy main thread** by channels. Understanding the message flow requires reading `crates/core/src/js_thread.rs`, `crates/core/src/plugin.rs`, `crates/core/src/protocol.rs` (a directory module — `protocol/{op,props,merge,style,…}.rs`), and `js/src/bridge.ts` together.

**Four ops** (`crates/core/src/js_thread.rs`) form the boundary:

- `op_flush(ops)` — JS→Bevy, sync. The reconciler batches a `Vec<Op>` per commit and flushes it. `serde_v8` deserializes straight into `protocol::Op` — no JSON strings on the hot path.
- `op_emit(name, value)` — JS→Bevy, sync, fire-and-forget app message.
- `op_request(id, name, value)` — JS→Bevy, sync; correlated request awaiting a reply.
- `op_next_event()` — Bevy→JS, **async** (Rust Future → JS Promise). Returns one `protocol::Outbound`.

**Channels** are created in `ReactUiPlugin::build` (`crates/core/src/plugin.rs`): crossbeam for JS→Bevy (`Vec<Op>`, `ReactMessage`, `RawRequest`), tokio mpsc for Bevy→JS (`Outbound`) and reload signals.

**`Outbound`** (`crates/core/src/protocol/outbound.rs`) is one internally-tagged enum (`uiEvent | event | response | reload`) carrying _everything_ Bevy sends to JS over a single channel. `js/src/bridge.ts`'s `runEventLoop` is a **router**: it `switch`es on the tag and dispatches UI events to React handlers (keyed by node id), named events to listeners, and responses to the awaiting promise. The reconciler→Bevy identity map is `NodeId(u32) → Entity` (`crates/core/src/bridge.rs`); node id `0` is the UI root. Requests carry their own `u64` correlation id.

The reconciler/render side lives in `js/src/` (`renderer.ts`, `mount.ts`, `bridge.ts`). The Bevy side that consumes ops and produces events: `crates/core/src/reconcile.rs` (`apply_js_ops`, `collect_ui_events`) and `crates/core/src/ui_map.rs` (op→`bevy_ui` component mapping).

**Updates are deltas — the only form.** `commitUpdate` diffs old/new props (`buildUpdateOp` in `bridge.ts` — handlers by presence, `style` field-by-field, everything else structurally) and emits `Op::Update { props, unset, styleUnset }` carrying only changed fields; a re-render with no value changes emits **no op at all**. Rust keeps the last applied props per node (`JsBridge::props_cache`), merges each delta (`Props::merge_delta` — absent = unchanged, `unset`/`styleUnset` = reset; a single `style_fields!` table in `protocol/style.rs` maps every style field to its wire name + "dirty group"), and re-applies **only the dirty groups** (`apply_style_masked` in `ui_map.rs`). Event-like props (`value`, `selection*`, `scrollTop/Left`, `draw`) are act-now, never cached. Event-loop consequence: op silence on an idempotent re-render is normal, so don't probe runtime liveness with a state-neutral click. Adding a `Style` field means extending the `style_fields!` table — a compile error + `protocol::style::tests` guard it.

## Architecture: hot reload (React Fast Refresh)

Editing a component **preserves its `useState`/hook state** (and live animations); only non-component edits or errors fall back to a full reload. The mechanism spans three layers — read `js_thread.rs`, `js/src/hmr.ts` + `renderer.ts` + `mount.ts`, and `js/build-lib.mjs` together:

- **The isolate stays alive.** `spawn_js_thread` builds the V8 isolate once (`build_runtime`: prelude → `vendor.js` → `app.js`, all via `execute_script` — the app bundle is a classic-script IIFE, **not** an ES module, so it can be re-run). On a reload signal it does **not** rebuild: `pump` returns control to Rust, `apply_update` re-`execute_script`s the rebuilt `app.js` into the **live** context, and the next `pump` drives the refresh. Only a sync error in the new bundle triggers a full `build_runtime` rebuild. The bundle path is the **app** bundle; `vendor.js` is its sibling.
- **The React root persists.** `renderer.ts` keeps the `reconciler` + `root` module-level (they live in the never-re-executed `vendor.js`) and calls **`reconciler.injectIntoDevTools(...)`** — required, or `performReactRefresh` is a silent no-op. `mount.ts` runs `reset()` + `createContainer` only on the **first** call (guarded by `globalThis.__hmr.mounted`); a re-execution instead calls `__hmr.applyUpdate()` (→ `performReactRefresh`) and re-parks the event loop.
- **Components are instrumented.** `build-lib.mjs` runs each app source through **SWC's react-refresh transform** (`jsc.transform.react.refresh`) in an esbuild `onLoad` plugin, post-processing `$RefreshReg$` ids to be module-unique. `app.js` externalizes react/bevy-react to `globalThis.__bevyVendor` (set by `vendor.js`) so re-running it does **not** recreate the reconciler. `hmr.ts` installs the refresh runtime (`injectIntoGlobalHook`) before the reconciler is created.

Because the whole app bundle is re-executed (every component becomes a fresh function), `performReactRefresh` re-renders the tree — picking up non-component edits too — while preserving hook state for signature-stable components. Headless coverage: `crates/core/tests/hot_reload.rs` (Rust isolate-persistence) and the cold path in `roundtrip.rs`.

## Architecture: typed, codegen-synced app messaging

Three app-level channels, all **typed in Rust and mirrored to TypeScript by codegen** (`ts-rs`). Each direction has an attribute macro (`crates/macros/src/lib.rs`), a registry resource, and a slot in the single exporter.

- **React→Bevy notify** — `#[react_message]` → `ReactPayload` (`crates/core/src/message.rs`). `emit(name, value)` routes by name, deserializes into the typed struct, and `commands.trigger`s it for observers. Register via `app.add_react_handler(observer)`.
- **React→Bevy request/response** — `#[react_request(name, response = T)]` → `ReactRequest` (`crates/core/src/request.rs`). Observed as `On<Request<T>>`; answered with `req.respond(value)`. The `Responder` is `Clone + Send`, so replies can be deferred across frames. Unknown name / malformed payload **reject** the JS promise (never hang). Register via `app.add_react_request_handler(observer)`.
- **Bevy→React events** — `#[react_event(name)]` → `ReactEvent` (`crates/core/src/event.rs`). Sent from any system via the `ReactEvents` system param (`events.send(&E)`). Register via `app.add_react_event::<E>()` so the exporter knows the type. JS subscribes with `bevy.on(name, cb)`.

### The codegen sync invariant (important)

The Rust binding structs are the **single source of truth**. `App::export_react_typescript(path)` (`crates/core/src/message.rs::render_typescript`) walks all the registries (messages, requests, events, **filters**) in one pass and writes a self-contained `bevy.ts`: per-payload type declarations, the `ReactMessages`/`ReactRequests`/`ReactEvents` maps, a `declare module "bevy-react"` block augmenting the `BevyFilters` interface with every registered filter's params type (without it the `filter` style is intentionally untyped-unusable — `FilterUse` collapses to `never`), typed `emit`/`request`/`on` wrappers, and a structured **`bevy` proxy** whose nested methods come from dotted request names (`"board.get"` → `bevy.board.get()`; a void/unit request payload → a zero-arg method).

- The example exposes this via `cargo run -p bevy-react --example demos -- --export-bindings <path>` (a flag handled in `examples/demos/main.rs` that builds a bare `App`, runs the shared `register_react_bindings` aggregating every demo's bindings, exports, and returns without `app.run()`). The npm convenience is `npm run bevy:generate -w demos`.
- **After changing any `#[react_message]`/`#[react_request]`/`#[react_event]`/`#[react_filter]`/`#[react_morph_filter]` type — or registering/unregistering a filter — regenerate** and commit `bevy.ts`. Output is deterministic (sorted); the CI guarantee is regenerate-then-`git diff --exit-code`. `bevy.ts` is `.prettierignore`d so prettier never fights the generator.
- App code imports the typed surface from `./bevy` (e.g. `import { bevy, emit } from "./bevy"`), **not** the untyped functions from `"bevy-react"`.

## Architecture: named nodes (the Bevy escape hatch)

Every element takes a `name` prop (`<node name="hud">`): it crosses as its own wire field, is cached like any prop, and lands on the entity as a Bevy `Name` (dynamic — a delta replaces it, `unset`/`""` removes it). Rust reaches React-created entities two ways: the public `ReactNode(NodeId)` marker (every bridge entity carries it — `Query<(Entity, &Name), With<ReactNode>>`, `Added`/`RemovedComponents<ReactNode>` for lifecycle) and the `ReactNodes` **system param** (`get`/`all`/`iter`/`contains` — a hash index living on `JsBridge.names`, maintained by the op-apply path in `crates/core/src/names.rs`; `apply_js_ops` is at Bevy's 16-param cap, which is why it's a SystemParam over the bridge and not a separate resource). Order consumers `.after(ReactApplySet)` (wraps `apply_js_ops` in `Update`) for same-frame mounts. Names are **not unique** (group semantics; `get` returns the first mounted and reports a `nameAmbiguous` devtools warning). `Name` on React nodes is **bridge-owned**, like every component the bridge writes (`Node`, colors, text, `ImageNode`, `Children`…) — the `ReactNode` rustdoc carries the list. Foreign Bevy children under a React node are deliberately unmanaged: they die with the parent (recursive despawn) but are orphaned by any sibling change (the hierarchy sync `replace_children` from the shadow tree). `<surface>` binds its texture with `target` (like `<portal>`); `name` is identity only. Demo: "Named nodes" (`examples/demos/scenes/named_pins.rs`).

## Architecture: composited layers & filters

Some styles promote a subtree to a **composited layer** (`crates/core/src/layer.rs` + `layer/render.rs`): `opacity` on a node with children (group-alpha web semantics; opt out with `groupAlpha: false`), a non-empty `filter` chain, a `transform3d` (presence, even identity `{}`), or `cache: "always"`/`"never"`. Promotion is render-side only — layout/picking/refs/animations untouched — via a custom pass over stock `bevy_ui_render` (public seams, no fork): the subtree is captured into an offscreen texture and composited back as one quad at its stacking position. Captures are **cached** (a clean layer skips its capture pass), and translation, group alpha, and filter params are **composite-time** — animating them never re-captures. `cache: "never"` opts a subtree out: it force-promotes but re-captures every frame — and dirties every enclosing layer too — the escape hatch for pixels written outside the dirt tracking's sight (a live `<portal>` render target, an app-owned texture); time-driven _filters_ don't need it (`USES_TIME` already re-runs their passes). Captures are also **clip-independent**: ancestor clipping (scrollports/viewport) never bakes into captured pixels — a main-world interior-clip cascade (`layer/clip.rs`) feeds an extract-window `CalculatedClip` swap (`layer/render/clip.rs`, invisible to main-world systems like picking), and the ancestor clip clamps the composite quad at draw time instead (web semantics: overflow clips the filtered _result_; scrolling a layer is always a cache hit, and a layer scrolled into view is correct by construction). Offscreen layers still capture when dirty (quad draws nothing) — known cost: invisible re-captures for continuously-animated offscreen subtrees.

The `filter` style is a chain of `{ name, params }` (one object or an ordered array; order = pass order). Each resolved pass is a fullscreen WGSL pass, run capture → ping-pong textures → composite. Pass shaders `#import bevy_react::filter` (the prelude in `crates/core/src/layer/filter_prelude.wgsl` owns the bind-group contract + vertex stage), name their entry point `fragment` (`filter` is a WGSL reserved word), and follow the prelude's premultiplied-alpha rules (color ops unpremultiply around the math; blur-like resampling must not). Pass UVs span the **inflated** capture (node rect + the chain's summed outset ring); the uniforms carry that inset (`content_inset`), and the prelude's `content_uv()`/`content_rect_size()` recover the node's border box — how `gradientMap` (multi-stop linear-gradient recolor) keeps its gradient anchored to the text box when chained with `outline` (alpha-dilation ring under the content) — text-effect built-ins alongside blur/bloom/`shadow` (offset + blurred drop shadow, bloom's reuse-blur pass structure) and the color ops. A custom filter is a `#[react_filter]` params struct + a shader asset, registered with `app.add_react_filter::<T>()` — in **both** the running app and the exporter path (keep the call in the shared `register_bindings` site), or the generated typing silently diverges from runtime; then regenerate `bevy.ts` (same codegen sync invariant as above). Regular filters and morph filters are **separate families** in one registry (`ReactFilter::IS_MORPH`): custom morphs use `#[react_morph_filter]` + `app.add_react_morph_filter::<T>()` (name/shader args only), land in the generated `BevyMorphFilters` interface (regular filters land in `BevyFilters`), and the split is enforced at resolve time — a morph name in a `filter`/`backdropFilter` chain warns (`filterParams`/`backdropFilterParams`) and skips the entry, a regular name in `morphFilter` warns (`morphFilterParams`) and snaps.

The `transform3d` style (`layer/transform3d.rs` + `layer/render/transform3d.rs`) applies a 3D perspective transform to the captured result at composite time — a per-quad matrix (dynamic-offset uniform, real `w` for perspective-correct interpolation, z flattened post-transform) reshapes the composite quad; animating it is composite-only dirt (never re-captures, never re-runs filter passes). Fixed field order (scale → rotateX/Y/Z → translate → self-`perspective`, around `origin`); ancestor clip clamps the transformed result fragment-side; nested transform3d flattens into the parent capture. **Picking follows the visual** (`layer/pick3d.rs`): a shared `PointerId::Custom` virtual pointer inverts the cursor through the layer's screen homography onto the untransformed layout rect, real-pointer hits on transformed members are suppressed, and `Interaction`/`RelativeCursorPosition`/cursor-icon are corrected from the virtual pointer — identity transforms keep all of it inert. `transition: { transform3d }` eases field-wise (perspective snaps at an orthographic endpoint; unsetting the whole field demotes + snaps — keep an identity `{}` when removal should ease); inline `{ animated }` wrappers drive single fields (degrees for rotations, like every rotation in the system — the 2D `rotate` binding is degrees too). Transformed quads are antialiased Chromium-style: ~1px analytic edge feather in the composite fragment (`EDGE_AA_INFLATE_PX`, quad inflated in pre-transform space), and the sampled texture of any `TRANSFORM3D`-reason layer carries a full mip chain (`layer/render/mips.rs` — downsample blit staged like filter runs, rebuilt only when level 0 rewrites, so cached/animated layers pay nothing) sampled trilinear+anisotropic for non-identity quads; while mips are stale/compiling the composite falls back to bilinear, never gates. v1 limits: nested transformed-in-transformed picks via the nearest root only; click-through _under_ the visual quad; magnified captures sample soft (1:1 capture).

**`backdropFilter`** is the fourth chain surface: same wire shape and registry as `filter`, but it filters **what is rendered behind the node** — v1: the camera's post-processed 3D frame only (UI painted beneath the node is not included) — and composites the result as an opaque quad one epsilon under the node's content quad. Mechanism (`layer/render/backdrop.rs`): a per-frame snapshot blit crop-samples the camera's main texture over the layer's (outset-inflated) capture rect inside `ui_layer_capture_pass` (the blit bind group is created **in the pass** — the ViewTarget's a/b main texture flips during PostProcess, so prepare-time binding races), then the chain runs over the snapshot with the snapshot bound as both pass-0 source and binding-3 `capture_texture`, so **every existing filter shader works unchanged** (the blit writes alpha 1.0 explicitly — opaque satisfies the premultiplied contract trivially). Everything mirrors `filter`: promotion (`PromotionReasons::BACKDROP`, presence union), a second resolver instance (`resolve_chains<BackdropInput, ResolvedBackdropChain>` — backdrop chains are **forced `always_dirty`**, the source is live), a second transition channel (`transition: { backdropFilter }`, same empty-chain snap — keep an identity entry for eased removal), inline `{ animated }` param wrappers, and `backdropFilter*` diag kinds. The frosted quad covers the node's border box (shrunk out of the blur-outset ring) and **respects `borderRadius`**: the composite fragment masks coverage with a rounded-box SDF ported from bevy_ui's own `ui.wgsl` (same layout-resolved `ComputedNode.border_radius` radii, same `saturate(0.5 − sd)` antialias convention), so the frost edge coincides with the node's painted rounded background; all-zero radii disable the term exactly (the `edge_feather` select pattern — content quads stay pixel-identical). Costs and v1 limits: snapshot + chain re-run every frame (the node's own capture still caches); the backdrop ignores `transform3d` (axis-aligned); a backdrop layer nested inside another promoted layer forces the whole enclosing chain to re-capture every frame (live pixels defeat ancestor caching by design); gating is graceful (a not-ready backdrop shows the unfiltered frame, never an invisible subtree).

**`morphFilter`** is the view-transition surface: `morphFilter: { key, name, params }` on a node freezes its previous rendered appearance when `key` changes (string|number; only a change triggers) and blends frozen → live content with the named two-input filter, driven by an engine-owned `progress` eased 0→1. The one channel with **built-in default timing** (300ms ease-in-out — `transition: { morphFilter }` overrides); first mount/no-capture snaps; a mid-flight key change freezes the in-flight blend and restarts (always smooth); unset demotes + snaps. Presence force-promotes (`PromotionReasons::MORPH` — a cached capture must exist to freeze). Mechanism: the transition channel (`transition/channels.rs::MorphChannel`) bumps `MorphState.freeze_seq` + pushes capture dirt; render-side (`layer/render/morph.rs`) the freeze **steals** the old texture (the capture, or an interrupted morph's blend — no blit/copy, survives reallocs) into `MorphSlot.snapshot` in `prepare_layer_textures`, and a per-frame blend pass writes a dedicated `blend` texture (binding 0 = live capture "to", binding 3 = snapshot "from", engine data in the **reserved param tail**: `params[7].x` = progress, `params[6]` spare — shader authors use the prelude's `morph_progress()`/`morph_sample_from()`/`morph_sample_to()`). A regular `filter` chain composes on top (morph first: the chain's pass 0 sources the blend); a morph-only composite samples the blend, gated like the filter gate. The frozen snapshot is **layout-anchored**: the blend stretches it onto the node's current capture rect (plain 0..1 UV over both textures), so scrolling or moving the node mid-flight carries both images together and never touches the capture rect (a mid-morph scroll stays a cache hit); a size change across the swap stretches the old appearance — handling that gracefully is the app's responsibility. Settle is invisible by the **progress-1 identity contract**: at `progress == 1.0` a morph shader must output exactly the source sample — the settle frame renders at 1.0 before the pass drops. Morph filters are their **own family** (registered via `#[react_morph_filter]` + `add_react_morph_filter`, typed by `BevyMorphFilters`): a regular filter name in `morphFilter` warns (`morphFilterParams`) + snaps. v1 caps: a morph filter must resolve to exactly ONE pass with user params ≤ 6 vec4s; built-ins `crossfade`, `linearWipe { angle, softness }`, and `pixelize`; morph _param_ `{ animated }` bindings ride the animation side (`morphFilter.<param>`, park nothing — progress is engine-owned). Known v1 limit: a morph-only layer under `transform3d` samples bilinear (no mips on the blend). **Empty layers are valid transparent captures**: a promoted layer whose subtree paints nothing still runs its (clear-only) capture pass and marks `content_valid`, and a MORPHING item-less layer's composite quad falls back to the root's own stacking position (`ExtractedLayer::fallback_sort_key`) — so the **empty-carrier idiom** works with no placeholder drawable: keep a nothing-painting carrier mounted, toggle its content in the same commit as the key flip, and the morph blends from/to genuinely empty pixels (the carrier must have rendered ≥1 frame before the first flip — a same-commit mount+flip adopts the key silently, the mount rule).

Runtime behavior worth knowing: `transition: { filter }` eases matching chains param-wise and fades trailing built-in adds/removes through identity values, but easing **to an empty chain snaps** (unset `filter` demotes the layer — there is no resolved chain left to write into), so keep an identity entry in the base style (e.g. `{ name: "blur", params: { radius: 0 } }`) when removal should fade. An inline `{ animated: sv }` wrapper on a param drives it per frame, values in wire units (px lengths, degree angles); the wrapper's optional `seed` is the static value the resolver decodes in its place (size it for the animation's range when the param feeds the capture outset, e.g. a blur radius). A filter pass whose shader fails to compile gates its layer's composite — the subtree is **invisible** until fixed — and warns naming the layer + the error (immediately on a hard compile error; after a hang threshold for a never-ready pipeline). The devtools Layers tab lists promoted layers with their chains and live param values. Gradients ease too: `transition: { backgroundGradient | borderGradient }` eases **strictly-matching** structures (same kind, stop count, colorSpace, per-stop position presence, radial shape variant) stop-wise — sRGB stop colors like `backgroundColor`, numeric long-way angles, same-unit `Val` lerp with per-leaf snap — and any structural mismatch **snaps immediately**, silently (deliberately unlike filter's 0.5-crossfade discrete swap); setting/unsetting a gradient snaps silently, so fade via transparent stops in the base style when appear/removal should ease. Gradient leaves also accept inline `{ animated }` wrappers (degree/px wire units; the apply stage rebuilds from the `GradientTargets` stamp, riding the same dirty groups): any binding parks that surface's whole transition channel, and mixing a binding with a transition spec on one surface warns (`gradientTransition`). `transition` channels are **explicit-only** — the `all` shorthand was removed (morphFilter keeps its built-in 300ms default). Filter `Angle` params lerp numerically (no shortest-arc wrapping — 350°→10° goes the long way). `transition: { borderRadius }` eases the corner radii per corner (same-unit corners interpolate, a corner changing unit snaps alone; unset eases to square) — the value lands on `Node.border_radius` (bevy keeps radii on `Node`), so like `size` every eased frame is a relayout, and the drive pushes content dirt (the radius is outside the layer geometry hash); a uniform `borderRadius: { animated }` binding (one px value for all corners — the `borderColor` precedent, no per-corner wrappers) parks the channel and is excluded from `has_node_props` (it never moves the rect).

**`transition: { layout }`** is the FLIP channel (`crates/core/src/transition/layout.rs`; the why lives in `docs/adr/0001-layout-transition-flip-on-global-transform.md`, the rules in the `LayoutChannel::drive` doc, the terms in `CONTEXT.md`). Operationally: `drive_layout_transitions` runs in `PostUpdate` `after(UiSystems::Layout)`, `before(UiSystems::PostLayout)` and before `sync_layer_geometry`, measures taffy's **rounded local** rect via `UiSurface::get_layout(entity, true)` and composes the delta into the animating subtrees' **`UiGlobalTransform`** (never `UiTransform` / `ComputedNode`); bevy re-derives pristine globals next frame, a settled node writes nothing, and the layer geometry gate (`Changed<UiGlobalTransform>`) repaints cached enclosing layers for free. Two couplings to keep: the channel adopts (instead of chasing) while the node's **own** layout writers are live — `TransitionState::size_in_flight` (generated from the `size` rows of `with_input_channels!`) plus one grace frame for the settle step, and `AnimatedBindings::has_node_props` — and a promoted root's capture window is the border box's **transformed AABB** (`sync_layer_geometry`), since the FLIP scale lands in its global. The FLIP scale is the node's own — children compose from the translated-but-unscaled frame, so a resizing container eases its box with crisp content (a `<text>`/`<image>` node's own paint does scale) — but its surroundings snap; a container that must re-flow its siblings uses the real-layout `size` channel with `layout` on the children (the demo pairing). Known v1 limit: a rect driven continuously by something the engine can't attribute (an ancestor's `size` ease, a window-resize drag) re-arms every frame — it lags, then catches up. Headless coverage: `transition/layout_tests.rs::layout_app` runs bevy's real `ui_layout_system` (the harness mirrors bevy_ui's own) — reuse it for anything that needs real layout.

**Shared elements** (`sharedTag` prop + `transition: { sharedElement }`; `crates/core/src/shared_tags.rs` pairs, `crates/core/src/transition/shared.rs` seeds, the why in `docs/adr/0002-shared-elements-seeded-first-sight.md`, the terms in `CONTEXT.md`). React has no reparenting, so a node that "moves" between parents/screens is an unmount + mount; the tag is the identity and **the commit is the trigger** (no imperative API). Pairing is a Rust pre-pass in `apply_js_ops` (only the shadow tree knows a removed subtree's contents — a screen swap emits ONE `Remove`), gated on the tag index being non-empty: same tag, same element kind (every node's kind is recorded in `SharedTags` since a later delta can add a tag), same UI root, same batch; the first mounted match seeds every incoming node with the tag, silently (no diag). Mechanics to keep: the outgoing entity is read by a command queued **before** any op's commands (its despawn is deferred like every command) into `PendingSharedSeeds`, and stamped as a `SharedSeed` by a command queued **after** the loop — `apply_js_ops` is at the 16-param cap, so both are `commands.queue` closures, not new system params; `stamp_pending` drops the seed unless the incoming style has a `sharedElement` spec (explicit-only, no default). The engine side is "seeded first sight": `drive_transitions` overlays the seed's value-channel currents (size rows excluded) so each block's ordinary retarget path arms from there, with `or_shared` falling back to the `sharedElement` spec while `TransitionState::shared.active`; the rect is parked for `drive_layout_transitions`, which converts it into the parent's layout space off this frame's pristine globals, seeds the layout channel (`LayoutChannel::seed_shared` — seed frame shows the seed rect via FLIP scale — with `ComputedNode.border_radius` divided out by that scale for the frame, or a seeded circle reads as a rounded square; bevy rewrites it from `Node` next frame — then translate-only with a moving target while the size flies; the seed stays **root-space anchored**: `SharedFlight::origin` is re-expressed in the parent's frame every flight frame via `rebase_shared`, so a parent the size flight re-flows — a centered container — never drags the take-off point along), and arms the measured-px size flight (`arm_shared_size` / `drive_shared_size`: `Node.width/height` ease in logical px from the seed's size to the natural size measured at first layout, settle restores the authored `Length`). v1 limits: two-commit mounts (Suspense) don't pair; the flight is clipped by the new parent like any layout transition; no completion callback; the natural size is measured once. Headless coverage: `shared_tags.rs` tests (pairing rules + end-to-end color seed), `transition/layout_tests.rs` (`shared_seed_*`).

## Architecture: SVG (files + JSX shapes)

Two web-faithful doors, one CPU raster core (`crates/core/src/svg/` — a leaf module like `canvas`): an `<image src="x.svg">` is extension-detected and re-rasterized per node at laid-out size × DPI (usvg parses once into an `SvgDocument` asset; resvg renders — resvg IS tiny-skia underneath; layout measures from the file's intrinsic size via a `ContentSize` stamp, decoupled from the re-rastered texture). `<svg>` is JSX-children-only: the 8 shape intrinsics (`circle`/`rect`/`path`/`g`/…) are **Node-less bridge entities** (the `textSpan` precedent) whose attrs cross as ONE atomically-replaced `shape` object (packed at the renderer like `anchor`; `js/src/svg.ts` owns `SHAPE_ATTR_KEYS` — a new attr MUST be added there or every re-render emits empty update ops) and paint depth-first via `svg/paint.rs` (no `viewBox` = logical-px space). Per-shape pointer events: `svg/pick.rs` refines the svg node's `PointerHits` into the topmost painted shape (shapes are spawned with a pass-through `Pickable` — bevy's hover map treats an absent one as blocking, which would hide the svg root and its ancestors, e.g. an enclosing `<button>`, from hover/press/click; pinned in `svg/pick/hover_tests.rs`) (kurbo hit-testing in `svg/hit.rs` mirrors the painter's geometry — a parity test pins the two backends); `svg/interact.rs` synthesizes `Interaction`/`RelativeCursorPosition`, and events carry **SVG user-space coords**. Numeric attrs accept `{ animated }` bindings (the driver writes into the wrapper's **seed slot** — `animations/shape_stage.rs`) and a `transition` prop on the shape eases static changes (`transition/shape_channel.rs`, state-owned-current; any shape-attr binding parks that shape's whole transition channel). **Write order is the invariant**: op merge → animation apply → transitions → raster read — declared and commented in `plugin.rs`'s canvas sub-tuple, each edge pinned by a named same-frame test. All re-raster dirt derives from `Changed<SvgShape>`/`Changed<Children>`/`RemovedComponents<Children>` — every writer is compare-before-write, so an idle frame ticks nothing. SVG `<text>` support in files is behind the off-by-default `svg-text` cargo feature (pulls fontdb).

## Architecture: `imageRendering` (raster resampling)

`imageRendering: "auto" | "bilinear" | "trilinear" | "nearest"` (`crates/core/src/image_rendering.rs`, the why in `docs/adr/0003-image-rendering-derived-variants.md`, the terms in `CONTEXT.md`) fixes large images drawn small: bevy loads a PNG with ONE mip level and samples `ImageNode`s with the **asset's** sampler (bind group cached per `AssetId`), so the mode has to change an asset. It never changes the source: an explicit mode binds the node to a **variant asset** per `(source, mode)` — cloned, sampler set, `trilinear` gets a CPU 2×2 box pyramid (`image_rendering/pyramid.rs`: linear light, alpha-weighted, `Rgba8Unorm(Srgb)` only) built on `AsyncComputeTaskPool` with the node staying on its source until it lands (no interim upload; a source modified mid-build is re-derived when it lands, never cancelled) — shared by every node asking for the pair, refcounted, dropped with its last user, rebuilt in place on source `Modified`, and only made when the source doesn't already satisfy the mode (`bilinear` on a plain PNG = no copy). `auto` is passive (no write). Mechanics: `apply_style_masked` stamps `ImageRenderingMode` (its own dirty group, content dirt); `bind_image_rendering` runs after every `ImageNode` handle writer (op drain, interaction restyle, `bind_background_textures`) and re-points on `Changed<ImageNode>`/mode — every handle write pushes layer content dirt — recognizing its own repoint echo through the variant→key reverse map (never a variant of a variant) and skipping the re-plan (and re-warn) when source+mode are unchanged (tint writes); a not-yet-loaded source is retried per frame (its old binding released first). "Satisfies" reads the host's real `ImagePlugin::default_sampler` (`ImageVariants::from_app`). Live textures (`RENDER_ATTACHMENT`, canvas, svg, `<portal>`/`{ texture }` bindings — their own systems rewrite the handle) are never copied **or written** (an in-place `Modified` re-uploads the CPU buffer over the GPU target): every explicit mode is refused there with one `imageRendering` diag warning, as are data-less sources. Compositing is untouched by design (non-3D layer composites are 1:1 blits; `transform3d` already mips). Headless coverage: `image_rendering/tests.rs` (two modes/one file, sharing, refcount drop, reload, live targets), `pyramid::tests` (pixel-exact levels).

## Conventions & gotchas

- **Bevy 0.19**, Rust **edition 2024**. The lib uses `extern crate self as bevy_react` so the macros' `::bevy_react::…` paths resolve inside the crate's own tests/examples.
- Macro-default names lowercase the **first letter** of the struct ident (`Count` → `"count"`); override with `name = "..."`. Dotted names (`"board.get"`) only make sense as explicit overrides and drive the nested proxy.
- `ts-rs` maps Rust integers to TS `number` (precision loss above 2^53 for `i64`/`u64`/`usize`). Newtype/unit structs flatten: `struct Count(usize)` → `type Count = number`, unit structs inline to `null`.
- `#[react_request]`/`#[react_event]` (like `#[react_message]`) expand to `::ts_rs::` and `::serde::` paths, so an external consumer crate must have those as direct deps. Works seamlessly in-repo because examples share the package's deps.
- The example UI lives in `examples/demos/ui` (the dir is `ui`, not `app`); the per-demo React components are under `ui/src/demos/`. It bundles with esbuild (`build` script in its `package.json`) to a single ESM file that `ReactUiPlugin` loads.
- The `canvas`, `svg`, `animations`, and `filters` modules each **own their wire types** (`DrawCmd`, `ShapeAttrs`/`ViewBox`/`PathData`, `AnimatedBindings`, `FilterChain`/`FilterUse`); `core`'s `protocol::props::Props` references them by module path (consumers import `crate::canvas::DrawCmd` etc. from the owning module — `protocol` re-exports nothing). `filters` additionally owns the `FilterRegistry` + built-ins, param packing (`ParamSlot`, no-straddle rule), and the resolve/interpolation primitives (`resolve_filter_chains`, `lerp_packed_params`). The dependency direction is module-level convention: the bridge machinery (`protocol`/`reconcile`/`ui_map`) reaches into `crate::canvas`/`crate::animations`/`crate::filters` — never the reverse — so adding a draw command, animation driver, or filter is a change in that module, not the bridge. (`layer::render` consumes `filters`' resolved chains; the filter resolve system reads `layer`'s promotion markers — that pair is deliberately coupled.)
- **Invalid-value warnings feed devtools — and `diag` is the only logger.** Every fall-back site reports through `crates/core/src/diag.rs`, which emits the terminal `warn!` itself (`diag::log_warn`, every build, deduped once per distinct `(kind, value, message)` per process — never add a site-level `warn!` next to a report, and never report per frame expecting the log to throttle beyond that) and, in `devtools`+debug builds, the structured mirror so the inspector can flag the offending row: serde-boundary fallbacks call `protocol::decode_warn(kind, value, msg)` (node id attributed per op by `protocol::OpBatch`, drained by the bridge tap via `op_take_decode_warnings`), apply-time parses call `diag::report` under a `diag::node_scope` (drained each frame → `devtools.warning` event, deduped). A new warn site's `kind` must appear in `js/src/devtools/warnings.ts` `KIND_FIELDS` — `devtools/js_tables.rs::js_warning_kind_table_covers_known_kinds` guards the list.
- **`<canvas>` is web-faithful retained pixels.** `CanvasSurface` keeps a persistent premultiplied pixmap plus persistent raster state (styles + current path survive across batches); paint **accumulates**. Two write paths: the declarative `draw` prop (clear + replay, still an act-now event field) and `Op::Draw` (append — the imperative path behind `<canvas ref>` → `getContext()`, whose commands batch on a microtask and flush outside React commits). A layout resize **clears** the surface (HTML width/height-set semantics) and `collect_canvas_resize_events` (core) sends a `"resize"` UiEvent with the new logical size — unconditionally, not gated on `onResize`: `bridge.ts` needs it to update the handle's `width`/`height` and to auto-replay a stored declarative painter (leading `Clear` + re-recorded list). Headless coverage: `roundtrip.rs::canvas_resize_replay_round_trip`.

### Screenshotting the demos app (visual verification)

To see a demo rendered — to verify a visual change or refresh a screenshot — use the example's built-in `--shoot` mode, **not** OS screen capture (`import`/`grim`/`scrot`/`xdotool`). Screen-grabbing grabs the wrong window on a shared/occluded desktop, and an occluded window's swapchain reads back as 1×1.

```sh
npm run build -w demos   # build the bundle first (shoot mode disables hot reload)
cargo run -p bevy-react --example demos -- --shoot "<portal>" out.png [settle_secs]
```

- The first arg is the demo's **left-nav label** (e.g. `"<portal>"`, `"<canvas>"`, `"Backdrop filters"`). The tool navigates the React gallery to it, waits `settle_secs` (default `3`) for the demo + its 3D scene to settle, captures, and exits on its own.
- It renders the whole app (3D scene + React UI) into an **offscreen `Image`** — the main `IsDefaultUiCamera` camera is re-pointed at it — and captures with Bevy's in-process `Screenshot::image(...)` + `save_to_disk`, so the result is independent of window focus/occlusion/surface (output is 1280×832). Still needs an X11 display present.
- Implementation: `examples/demos/screenshot.rs` (the `Shoot` state machine + camera redirect). Navigation rides a `debug.selectDemo` `#[react_event]` that `examples/demos/ui/src/App.tsx` subscribes to (`findDemoByLabel`); the `--shoot` flag is parsed and wired in `examples/demos/main.rs`. After changing the event type, regenerate `bevy.ts` like any other binding.
